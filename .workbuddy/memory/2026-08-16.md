# 2026-08-16

## 修复 dsh-vision-plugin 启动崩溃 (Config.parse is not a function)

- **现象**: `npx @deepseek-ai/dsh web` 和 Desktop 端启动都报 `Config.parse is not a function`，整个 plugin tree 加载失败。
- **根因**: 插件把 `@deepseek-ai/schemastery` 当 zod 用了。schemastery 的 schema 是**可调用函数**（`schema(value)` 返回归一化值/抛 ValidationError），没有 `.parse` 方法。dsh-settings 内部也是 `schema(mergeLayers(base, section))` 这样调用的，证实生态约定就是 callable 风格。
- **修复** (commit 9e3adb8, lib/index.js): 新增 `parseConfig()` —— 优先 `Config(v)` 直接调用，回退 `.parse` / `~standard.validate`；解析失败时 warn + 回退纯默认值，不再拖垮整个插件树。
- **部署**: `git push origin main` 后在 `~/.dsh/profiles/web/` 跑 `pnpm update dsh-vision-plugin`（lockfile 原本锁死旧 commit 0950c12，普通 pnpm install 不会拉新提交）。pnpm 把 git 依赖换成了 codeload tarball 格式解析，属正常。
- **验证**: 真实启动 `dsh web` 成功（http://127.0.0.1:3080），boot manifest 含 `dsh-vision-plugin` 条目，`apply()` 全链路 smoke test 通过（adapter 注册、3 个 tool 注册、settings inject 正常）。
- **注意**: Desktop app 的 host 复用 `~/.dsh/profiles/web` 的 node_modules（同一 profile），web 更新后 desktop 重启即生效。
